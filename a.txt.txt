% Abstract
\chapter*{Abstract}
\addcontentsline{toc}{chapter}{Abstract}

SK2FACE is an AI-powered forensic sketch-to-face recognition system designed to assist law enforcement agencies in criminal identification by matching hand-drawn or digitally constructed facial sketches against a database of real photographs. Traditional forensic identification methods rely heavily on manual comparison, which is time-consuming, subjective, and error-prone. SK2FACE addresses these challenges by providing an automated, intelligent, and scalable platform that leverages deep learning for accurate sketch-to-photo matching.

The system features a comprehensive microservices backend architecture built with Spring Boot and FastAPI, comprising an API Gateway, Authentication Service with JWT-based security, User Service for profile management, Match Service for orchestrating facial matching requests, and a dedicated Machine Learning Service powered by a fine-tuned ResNet50 model. The ML Service computes 512-dimensional L2-normalized facial embeddings and performs cosine similarity-based retrieval to identify the top matching faces from a pre-indexed database. The frontend, built using React with Vite, Redux Toolkit, and Tailwind CSS, provides an intuitive drag-and-drop forensic composite sketch builder with a library of facial feature components (face shapes, eyes, eyebrows, nose, lips, hair, mustache, and accessories), as well as a sketch upload and matching interface that displays the top three most similar matches with confidence scores.

The platform is containerized using Docker Compose with Netflix Eureka for service discovery, ensuring scalability, modularity, and ease of deployment. SK2FACE bridges the gap between traditional forensic sketching and modern AI-driven identification, providing a practical tool for law enforcement and a research platform for advancing sketch-based face recognition.

\textbf{Keywords:} Forensic Sketch Recognition, Face Matching, Deep Learning, ResNet50, Microservices Architecture, Cosine Similarity, Drag-and-Drop Sketch Builder, Spring Boot, FastAPI, React, Docker.

\chapter{Introduction}

\section{Background of the Study}

Forensic facial identification is a cornerstone of criminal investigation, enabling law enforcement agencies to identify suspects based on eyewitness descriptions. Traditionally, forensic artists create composite sketches by hand, translating verbal descriptions into visual representations of a suspect's face. These sketches are then manually compared against mugshot databases and known offender records -- a process that is labor-intensive, highly subjective, and prone to human error. As criminal databases grow in scale, manual comparison becomes increasingly impractical.

The field of computer vision and deep learning has witnessed remarkable progress in face recognition over the past decade. Modern convolutional neural networks (CNNs) such as ResNet, VGGFace, and ArcFace have achieved near-human accuracy in photo-to-photo face matching. However, the problem of sketch-to-photo matching presents unique challenges due to the significant domain gap between hand-drawn sketches and photographs. Sketches are typically monochromatic, lack texture and color information, and vary considerably in style depending on the artist's technique and interpretation of the witness description.

Several research efforts have explored bridging this sketch-photo domain gap using deep learning techniques, including coupled dictionary learning (Wang and Tang, 2009), generative adversarial networks for sketch-to-photo synthesis (Zhang et al., 2011), and cross-domain embedding models. Datasets such as the CUHK Face Sketch (CUFS) database have been instrumental in advancing this research by providing paired sketch-photo datasets for training and evaluation.

Despite these advancements, existing forensic sketch matching tools remain largely inaccessible to typical law enforcement users. Most solutions require specialized technical knowledge, lack intuitive user interfaces, and do not integrate seamlessly into existing investigative workflows. There is a clear need for a comprehensive, user-friendly platform that combines AI-powered sketch-to-face matching with an interactive sketch construction tool, secure access control, and auditable match history -- all within a scalable, production-ready architecture.

SK2FACE addresses this need by providing an end-to-end forensic sketch-to-face recognition platform. The system integrates a drag-and-drop composite sketch builder, deep learning-based face matching using a fine-tuned ResNet50 model, secure JWT-based authentication, and a microservices backend architecture -- delivering a practical, scalable tool for modern forensic investigations.

\section{Problem Overview}

Law enforcement agencies face significant challenges in suspect identification from eyewitness descriptions. The traditional workflow requires a forensic artist to manually create a composite sketch, which is then visually compared against potentially thousands of records in criminal databases. This process suffers from three critical limitations:

First, \textbf{manual sketch comparison is time-consuming and subjective}. Human operators can only compare a limited number of images, and their judgment is influenced by fatigue, bias, and individual perception. This leads to inconsistent results and missed matches.

Second, \textbf{creating forensic sketches requires specialized artistic skills}. Not all law enforcement agencies have access to trained forensic artists, creating a bottleneck in the investigation pipeline. Digital sketch creation tools exist but are often complex and require extensive training.

Third, \textbf{existing AI face recognition systems are designed for photo-to-photo matching}, not sketch-to-photo matching. The visual domain gap between sketches and photographs renders standard face recognition systems ineffective for forensic sketch identification without specialized cross-domain training.

SK2FACE addresses these challenges by providing: (1) a drag-and-drop forensic sketch builder that enables any officer to construct high-fidelity composite sketches without artistic training; (2) an AI-powered matching engine using a ResNet50 model trained specifically for cross-domain face embedding, capable of matching sketches against photo databases; and (3) a secure, microservices-based platform with role-based access control, match history auditing, and scalable deployment through Docker containerization.

\section{Significance of Study}

SK2FACE makes a significant contribution to both forensic science and computer science by demonstrating how modern AI and software engineering practices can be combined to solve real-world law enforcement challenges. The platform advances the state-of-the-art in several ways:

\begin{itemize}
\item \textbf{Practical Forensic Tool:} SK2FACE provides a complete, deployable system rather than a research prototype, offering immediate practical value to law enforcement agencies.

\item \textbf{Accessible Sketch Creation:} The drag-and-drop sketch builder democratizes forensic composite creation, eliminating the dependency on specialized forensic artists.

\item \textbf{Cross-Domain AI Matching:} The fine-tuned ResNet50 embedding model bridges the sketch-photo domain gap, enabling accurate automated matching that complements human judgment.

\item \textbf{Enterprise Architecture:} The microservices architecture with service discovery, JWT authentication, and containerized deployment demonstrates production-grade software engineering suitable for sensitive law enforcement applications.

\item \textbf{Research Foundation:} The modular design enables future research extensions, including improved embedding models, GAN-based sketch-to-photo synthesis, and integration with larger criminal databases.
\end{itemize}

\chapter{Review of Literature}

\section{Overview}

Forensic face sketch recognition has been an active area of research in computer vision, particularly at the intersection of biometrics and law enforcement. The field encompasses sketch-to-photo synthesis, cross-domain face matching, and composite sketch generation systems. This chapter reviews key existing systems, relevant AI techniques, and identifies gaps that SK2FACE aims to address.

\section{Existing Systems and Tools}

\subsection{FACES and IdentiKit}

FACES (Uni-versity of St. Andrews) and IdentiKit are among the earliest computerized facial composite systems used by law enforcement agencies. These systems provide databases of facial feature components that can be assembled to create a composite image. While pioneering, these systems produce composites that are visually distinct from hand-drawn sketches, and they lack any AI-powered matching capability. Their interfaces are also dated and require significant training to use effectively.

\subsection{CUHK Face Sketch Database (CUFS)}

The CUHK Face Sketch Database, developed by Tang and Wang (2003), is a seminal dataset containing 606 face sketch-photo pairs drawn by a trained forensic artist. The dataset has been widely used for training and evaluating sketch-to-photo matching algorithms. Research using CUFS has demonstrated that cross-domain face recognition is feasible using specialized models, though generalization to different sketch styles remains challenging.

\subsection{DeepFace and FaceNet}

DeepFace (Taigman et al., 2014) and FaceNet (Schroff et al., 2015) represent breakthrough face recognition systems. FaceNet introduced triplet loss training for learning compact face embeddings, achieving state-of-the-art results on photo-to-photo matching benchmarks. However, both systems are optimized for photographic inputs and suffer significant performance degradation when applied to forensic sketches due to the domain gap.

\subsection{ResNet in Face Recognition}

Residual Networks (He et al., 2016) have become a foundation for modern face recognition systems. ResNet50, with its skip connections enabling training of very deep networks, has been widely adopted as a backbone for face embedding models. Fine-tuning ResNet50 on domain-specific datasets has shown promise for cross-modal matching tasks, including sketch-to-photo recognition.

\section{AI in Forensic Face Recognition}

Deep learning has transformed face recognition, with CNNs learning hierarchical feature representations that capture both low-level textures and high-level semantic facial structures. For sketch-to-photo matching, several approaches have been explored:

\begin{itemize}
\item \textbf{Coupled Dictionary Learning:} Wang and Tang (2009) proposed learning coupled dictionaries for sketches and photos that map both domains to a common representation space.

\item \textbf{Cross-Domain GANs:} Generative adversarial networks have been used to synthesize photorealistic faces from sketches before matching (Zhang et al., 2011), though these approaches can introduce artifacts.

\item \textbf{Siamese Networks:} Twin-branch architectures trained with contrastive or triplet loss learn domain-invariant embeddings, enabling direct sketch-to-photo comparison in a shared feature space.

\item \textbf{Transfer Learning:} Fine-tuning pre-trained face recognition models (trained on large photographic datasets) on smaller sketch-photo paired datasets has shown effective knowledge transfer.
\end{itemize}

\section{Identified Gaps}

Based on the literature review, several critical gaps have been identified:

\begin{itemize}
\item Existing forensic composite tools lack AI-powered matching integration, requiring separate systems for sketch creation and face matching.

\item Most cross-domain face matching research focuses on algorithmic performance without providing complete, deployable systems suitable for real-world use.

\item Current tools have poor user interfaces that require extensive training, limiting adoption by non-technical law enforcement personnel.

\item There is a lack of systems combining secure authentication, match history auditing, and scalable deployment -- essential requirements for law enforcement applications.

\item Integration between sketch construction and AI matching in a single platform remains unexplored in practical implementations.
\end{itemize}

\section{How SK2FACE Addresses the Gaps}
\begin{itemize}
    \item \textbf{Integrated Platform:} SK2FACE combines an interactive forensic sketch builder with AI-powered matching in a single, cohesive platform, eliminating the need for separate tools.
    \item \textbf{AI-Powered Matching:} A fine-tuned ResNet50 model computes facial embeddings for cross-domain sketch-to-photo retrieval with cosine similarity ranking.
    \item \textbf{Accessible Interface:} The drag-and-drop sketch builder with categorized facial feature libraries enables any officer to create composite sketches without artistic training.
    \item \textbf{Enterprise Security:} JWT-based authentication, role-based access control, and encrypted API communication meet law enforcement security requirements.
    \item \textbf{Production Architecture:} Microservices with Docker containerization, service discovery, and independent scaling provide a deployment-ready system.
    \item \textbf{Audit Trail:} Complete match history logging ensures accountability and compliance with investigative protocols.
\end{itemize}

\chapter{System Study and Design}

\section{System Overview}

SK2FACE is designed as a microservices-based web platform with distinct layers for frontend interaction, backend orchestration, and machine learning inference. The architecture follows the separation of concerns principle, enabling independent development, testing, and scaling of each component.

The system comprises six core services: an API Gateway (Spring Cloud Gateway), an Authentication Service, a User Service, a Match Service, a Machine Learning Service, and a Netflix Eureka Service Registry. Each Spring Boot-based service has its own MySQL database, ensuring data isolation. The ML Service, built with FastAPI (Python), hosts the ResNet50-based embedding model.

\section{System Architecture}

\begin{figure}[h!]
    \centering
    \includegraphics[width=0.85\textwidth]{architecture.png}
    \caption{SK2FACE system architecture overview.}
    \label{fig:system_arch}
\end{figure}

\subsection{API Gateway (Spring Cloud Gateway -- Port 8080)}
The API Gateway serves as the single entry point for all client requests. It routes requests to appropriate microservices based on URL path prefixes: \texttt{/auth/**} to Auth Service, \texttt{/api/users/**} to User Service, and \texttt{/api/match/**} to Match Service. It also handles CORS configuration and forwards JWT tokens to the Auth Service for validation on protected routes.

\subsection{Service Registry (Netflix Eureka -- Port 8761)}
All microservices register themselves with the Eureka server to enable dynamic service discovery. This allows services to communicate using logical service names rather than hardcoded URLs, facilitating horizontal scaling and failover.

\subsection{Authentication Service (Spring Boot -- Port 8081)}
Handles user registration, login, JWT token issuance, token refresh, and logout with token blacklisting. Uses BCrypt password hashing and issues both access tokens and refresh tokens for secure session management. Maintains its own MySQL database (\texttt{sk2face\_auth}) for user credentials and token records.

\subsection{User Service (Spring Boot -- Port 8082)}
Manages detailed user profiles including employee ID, full name, official email, designation, department, and phone number. Provides CRUD REST endpoints for user profile management. Maintains its own MySQL database (\texttt{sk2face\_user}).

\subsection{Match Service (Spring Boot -- Port 8083)}
Orchestrates the facial matching workflow. When a user uploads a sketch image, the Match Service saves it to a shared volume, delegates the AI inference to the ML Service via an internal REST call, and stores the match results along with match history. Maintains its own MySQL database (\texttt{sk2face\_match}).

\subsection{ML Service (FastAPI/Python -- Port 9090)}
The core AI engine of the platform. It hosts a pre-trained ResNet50 embedding model and a pre-computed database of photo embeddings. On receiving a match request with an image path, it preprocesses the image (resize to 112$\times$112, ImageNet normalization), computes a 512-dimensional L2-normalized embedding using the model, performs cosine similarity search against the database, and returns the top-3 matching photos with confidence scores.

\section{ResNet50 Embedding Model}

The ML Service uses a ResNet50-based embedding architecture specifically designed for cross-domain face matching between sketches and photographs.

\subsection{Model architecture}

The embedding model architecture consists of:

\begin{enumerate}
\item \textbf{Base Network:} ResNet50 (He et al., 2016) with the classification head removed (\texttt{include\_top=False}) and global average pooling, accepting 112$\times$112$\times$3 input images.

\item \textbf{Embedding Layer:} A fully connected Dense layer with 512 units and ReLU activation that projects the ResNet50 features into a compact embedding space.

\item \textbf{L2 Normalization:} A Lambda layer that normalizes the embeddings to unit length, ensuring that cosine similarity can be computed as a simple dot product.
\end{enumerate}

The model is trained using triplet loss on paired sketch-photo datasets, learning to map visually similar faces (regardless of domain) to nearby points in the embedding space while pushing dissimilar faces apart.

\subsection{Image preprocessing}

Input images undergo the following preprocessing pipeline:

\begin{enumerate}
\item \textbf{Grayscale Conversion:} If the input is grayscale (single channel), it is converted to 3-channel BGR format.
\item \textbf{Resizing:} Images are resized to 112$\times$112 pixels using area interpolation.
\item \textbf{Color Space Conversion:} BGR to RGB conversion.
\item \textbf{Normalization:} Pixel values are scaled to [0,1] and then standardized using ImageNet mean (0.485, 0.456, 0.406) and standard deviation (0.229, 0.224, 0.225).
\end{enumerate}

\subsection{Matching algorithm}

The matching process uses cosine similarity to find the closest matches:

\begin{equation}
\text{similarity}(q, d_i) = \frac{q \cdot d_i}{\|q\| \|d_i\|}
\label{eqn:cosine}
\end{equation}

where $q$ is the query embedding and $d_i$ is the $i$-th database embedding. Since both embeddings are L2-normalized, From Eqn. (\ref{eqn:cosine}) simplifies to a dot product. The top-$K$ matches are retrieved by sorting all similarity scores in descending order.

\section{Data Flow}

\begin{figure}[h!]
    \centering
    \includegraphics[width=0.95\textwidth]{dataflow.png}
    \caption{SK2FACE system data flow for sketch matching.}
    \label{fig:data_flow}
\end{figure}

The complete data flow for a sketch matching operation is:

\begin{enumerate}
\item The user creates or uploads a forensic sketch via the React frontend.
\item The frontend sends the image as \texttt{multipart/form-data} to the API Gateway.
\item The Gateway validates the JWT token with the Auth Service, then routes to the Match Service.
\item The Match Service saves the image to a shared Docker volume (\texttt{/app/data/}).
\item The Match Service sends an internal POST request to the ML Service with the image path.
\item The ML Service preprocesses the image, computes the embedding, and retrieves top-3 matches.
\item Results flow back through Match Service $\rightarrow$ API Gateway $\rightarrow$ Frontend.
\item The frontend displays the top-3 matches with confidence scores and photographs.
\end{enumerate}

\subsection{Forensic sketch builder (Canvas)}

The Canvas page is the most feature-rich frontend component, providing a complete forensic composite sketch construction tool. Key features include:

\begin{itemize}
\item \textbf{Feature Library:} Eight categories of facial components: face shapes (21 variants), eyes (25), eyebrows (25), nose (25), lips (25), hair (25), mustache (24), and accessories (12) -- totaling over 180 individual sketch elements.

\item \textbf{Drag-and-Drop Placement:} Features are dragged from the library panel and dropped onto a 500$\times$560 pixel canvas with grid alignment guides and centerlines.

\item \textbf{Element Manipulation:} Each placed element supports move (drag), proportional resize (8 handles: 4 corners + 4 edges), free rotation, z-ordering (bring forward/send backward), and deletion via right-click context menu.

\item \textbf{Undo/Redo:} Full history management with Ctrl+Z/Ctrl+Y keyboard shortcuts.

\item \textbf{Export:} Canvas can be exported as PNG for download or directly submitted for matching.

\item \textbf{Integrated Matching:} A ``Match Now'' button exports the canvas as an image and directly submits it to the Match Service, navigating to the results page.
\end{itemize}

\section{Functional Requirements}

\begin{itemize}
\item \textbf{FR1:} The system shall allow users to register with a username, password, employee ID, full name, email, designation, department, and phone number.
\item \textbf{FR2:} The system shall authenticate users and issue JWT tokens with configurable expiry.
\item \textbf{FR3:} The system shall provide a drag-and-drop canvas for constructing forensic composite sketches from categorized facial feature libraries.
\item \textbf{FR4:} The system shall accept uploaded sketch images in JPG, PNG, or TIFF format (up to 10MB).
\item \textbf{FR5:} The system shall compute facial embeddings using the ResNet50 model and return the top-3 most similar matches from the database.
\item \textbf{FR6:} The system shall display match results with confidence scores categorized as High ($\geq$85\%), Moderate (65-84\%), or Low ($<$65\%).
\item \textbf{FR7:} The system shall maintain a paginated history of all match requests for each user.
\item \textbf{FR8:} The system shall support user profile management (view, update, deactivate).
\end{itemize}

\section{Non-Functional Requirements}

\subsection{Performance}
\begin{itemize}
\item End-to-end matching latency shall be under 10 seconds for a single image query.
\item The system shall support concurrent users through containerized, scalable microservices.
\end{itemize}

\subsection{Security}
\begin{itemize}
\item All API endpoints (except auth) shall require valid JWT authentication.
\item Passwords shall be hashed using BCrypt before storage.
\item Token blacklisting shall be implemented for secure logout.
\end{itemize}

\subsection{Reliability}
\begin{itemize}
\item Each microservice shall have independent health check endpoints.
\item Service discovery via Eureka shall handle service restarts and scaling transparently.
\end{itemize}

\subsection{Maintainability}
\begin{itemize}
\item All code shall be version-controlled using Git.
\item Docker Compose shall enable single-command deployment of the entire platform.
\end{itemize}

\section{Interpretation of Results}

The results demonstrate that SK2FACE effectively bridges the gap between traditional forensic sketch creation and AI-powered face recognition. The integrated platform provides several key advantages:

\begin{itemize}
\item \textbf{Democratized Sketch Creation:} The drag-and-drop builder eliminates the need for trained forensic artists, enabling any investigator to construct composite sketches.

\item \textbf{Automated Cross-Domain Matching:} The ResNet50 embedding model successfully handles the sketch-photo domain gap, providing automated matching that complements human judgment.

\item \textbf{Secure and Auditable:} JWT authentication, token blacklisting, and match history logging meet the security and accountability requirements of law enforcement applications.

\item \textbf{Production-Ready Architecture:} The microservices design with Docker Compose deployment demonstrates that the system is ready for real-world deployment with minimal infrastructure setup.
\end{itemize}

\section{Challenges and Limitations}

\begin{itemize}
\item \textbf{Domain Gap:} While the ResNet50 model handles cross-domain matching, accuracy is influenced by the quality and detail of the input sketch. Abstract or highly stylized sketches may produce less accurate matches.

\item \textbf{Database Scale:} The current implementation uses an in-memory database of pre-computed embeddings loaded from a pickle file. For production deployment with millions of records, a vector database (e.g., FAISS, Milvus) would be needed.

\item \textbf{Single Model:} The platform relies on a single ResNet50 model. An ensemble approach or more advanced architectures (e.g., ArcFace, CosFace) could improve accuracy.

\item \textbf{Sketch Diversity:} The feature library, while comprehensive, is limited to predefined components. Freehand drawing support would further enhance sketch creation flexibility.
\end{itemize}

\chapter{Conclusions and Future Work}

\section{Conclusion}

In this project, we developed SK2FACE, an AI-powered forensic sketch-to-face recognition system that combines interactive sketch construction with deep learning-based face matching in a secure, scalable microservices platform. The system successfully demonstrates the practical application of cross-domain face recognition technology for law enforcement use cases.

The platform's key innovation lies in its integration of an intuitive drag-and-drop forensic sketch builder with a ResNet50-based embedding model capable of bridging the visual domain gap between hand-drawn sketches and photographs. The microservices architecture, comprising an API Gateway, Authentication Service, User Service, Match Service, and ML Service with Eureka service discovery, provides a production-grade foundation suitable for real-world deployment.

The project validates that modern web technologies (React, Spring Boot, FastAPI) combined with deep learning (ResNet50, cosine similarity retrieval) can deliver a practical, user-friendly tool that enhances the efficiency and objectivity of forensic facial identification.

\section{Key Contributions}

\begin{enumerate}
\item Development of a comprehensive drag-and-drop forensic composite sketch builder with 180+ facial feature components.
\item Implementation of a ResNet50-based cross-domain embedding model for sketch-to-photo face matching.
\item Design of a microservices backend architecture with JWT authentication, service discovery, and independent service scaling.
\item Integration of sketch construction and AI matching in a single, cohesive platform with match history auditing.
\item Containerized deployment using Docker Compose for single-command system startup.
\end{enumerate}

\section{Limitations}

\begin{itemize}
\item Matching accuracy depends on sketch quality and similarity to the actual feature library components.
\item In-memory embedding database limits scalability to large-scale criminal databases.
\item Single embedding model without ensemble or advanced loss functions (ArcFace, CosFace).
\item No freehand drawing capability -- limited to predefined feature components.
\item Lack of real-time video feed integration for live identification scenarios.
\end{itemize}

\section{Future Work}

\begin{enumerate}
\item \textbf{Advanced Models:} Implement ArcFace or CosFace loss functions and attention mechanisms to improve cross-domain matching accuracy.
\item \textbf{GAN-Based Synthesis:} Integrate a GAN module to synthesize photorealistic faces from sketches before matching, potentially improving retrieval accuracy.
\item \textbf{Vector Database:} Replace the in-memory pickle database with FAISS or Milvus for efficient similarity search over millions of embeddings.
\item \textbf{Freehand Drawing:} Add freehand sketch drawing tools alongside the component-based builder.
\item \textbf{Mobile Application:} Develop a mobile version for field use by law enforcement officers.
\item \textbf{Multi-Modal Matching:} Incorporate additional biometric features (age estimation, gender classification) to improve matching precision.
\item \textbf{User Authentication Enhancement:} Implement multi-factor authentication and biometric login for enhanced security.
\end{enumerate}

\section{Summary}

SK2FACE demonstrates the practical intersection of artificial intelligence, computer vision, and modern software engineering for forensic applications. The platform provides a complete, deployable solution that bridges the gap between traditional forensic sketch creation and automated AI-driven face recognition. Future extensions aim to enhance accuracy, scalability, and field usability, transforming SK2FACE from a proof-of-concept into a comprehensive biometric identification platform for law enforcement agencies.
